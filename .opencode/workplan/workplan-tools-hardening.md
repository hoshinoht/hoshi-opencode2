### Settled interface and safety contracts

These contracts are owned by the parent and implemented by the core owner. Export names/internal module placement are reversible; the behaviors below are not worker latitude. Record any evidence-driven amendment surgically before dependent dispatch.

**A. Schema and compatibility**

1. One authoritative Zod module owns known V2 document types/statuses, sidecar shapes, and tool argument definitions. Core execution validates arguments even when called directly. Native registrations derive schemas from those argument definitions, removing only native-disallowed root overrides and tightening native concurrency requirements through shared refinements. Do not maintain parallel property maps.
2. Distinguish compatible storage shape from executable structural validation: incomplete drafts created/reset by existing APIs may have empty phases/steps or missing actions/validation; `validate` and CLI report these as field-specific structural issues. Readers safely parse compatible drafts rather than crashing. Strict readiness criteria in the artifact contract remain unchanged.
3. Preserve valid legacy optional `specFiles`/finding statuses, existing known fields, and unknown document metadata rather than stripping it on mutation. Defaults/normalized paths may be used in memory; reads never persist them. Invalid known fields/version/status/ID-vs-filename produce precise field paths. Ambiguous duplicate IDs block targeted operations; validation/doctor explain them without migration.
4. A shared artifact classifier excludes recognized checkpoints, dependency sidecars, locks, journals and archives from primary-plan enumeration. Malformed primary plans are surfaced per item rather than making doctor/list crash or being silently ignored. Reject symlinks and workspace escapes using existing guards plus canonical-root checks; validate nonempty linked files.

**B. Snapshot and concurrency**

1. `planHash` is a versioned SHA-256 digest over a canonical, sorted manifest of normalized relative paths and exact byte hashes for JSON, linked Markdown, and every linked spec. Encode missing files explicitly for diagnostics; a missing/unsafe required artifact cannot be called fresh. JSON includes the link set, so adding/removing/relinking specs invalidates freshness. Stable reads recheck the whole manifest, not only JSON timestamps.
2. `stateHash` additionally binds optional checkpoint, dependency sidecar, and any pending transaction identity/content. Public read/inspect/resume/preview/mutation results return `stateHash` as the next `expectedHash`; doctor can return it for invalid/interrupted state so recovery is possible. Internal temporary/lock files are not semantic state. `planHash` and `stateHash` are separate to avoid checkpoint self-reference.
3. `expectedHash` remains optional for legacy direct callers, but is required for all native existing-state writes, including patch/reset/checkpoint/compact apply and recovery. Check it against a stable snapshot under lock and after authorization; reject missing/stale hashes with current hashes and reread/recompute instructions, never auto-rebase stale patches.
4. Native create defaults to **must be absent**, checked under lock for JSON, destination Markdown and recognized state sidecars; it needs no previously retrieved hash. Existing-state overwrite requires explicit overwrite intent plus `expectedHash`, and cannot overwrite an unrelated destination Markdown. Preserve legacy create arguments while refusing silent collision.

**C. Mutation engine, locks and recovery**

1. All core writers (create/update/patch/reset/checkpoint/compact apply, dependency metadata updates and recovery) use one engine with injected `authorize(intent, invocation)` and optional legacy/mandatory native AbortSignal. Plan operations compute the complete write/read intent, allocate exact archive/staging/journal paths, get authorization, acquire the canonical per-plan cooperative lock, reread/revalidate, then commit. Denied/cancelled authorization creates no plan/archive/checkpoint/staging/lock/journal content. Check the signal before each operation/publication and completion, including after approval and awaited I/O; aborted invocation cannot publish a late commit or return success. Cancellation after authorized staging/partial publication leaves explicit recovery-required journal state; only necessary resource/lock cleanup is allowed, never implicit rollback/continued publication after abort. Revalidate actual paths/links immediately before file actions. Do not hold a writer lock across a user permission prompt.
2. Cooperative lock uses exclusive acquisition and owner metadata (hostname, PID, nonce, start time). Default bounded wait **5 seconds**, interruptible through the injected signal; native mutation requires a usable runtime signal. Auto-reclaim only same-host ownership positively proven dead, with unchanged owner identity and a **5-minute** abandonment grace; never reclaim live/PID-reused/foreign/unknown ownership solely by timeout. Inconclusive ownership fails closed with doctor/recovery pointers. Acquisition/reclaim/release must not unlink a replacement owner's lock. Cover separate processes, not just in-memory promises.
3. Acquire a **workspace-wide mutation/linkage lock before the per-plan lock**, after authorization, and hold both from destination ownership preflight through publication or explicit recovery outcome. Use the same safe owner/reclaim/release rules; include both exact lock paths in authorization. This serializes different-plan create/create and move/move claims to one absent Markdown. Ownership checks include pending transaction destination claims; refuse destinations owned/claimed by another plan and fail closed on ambiguous/corrupt claims. Do not silently migrate plans. Separate-process barrier tests require one winner, no overwritten bytes and no duplicate ownership. Specs are read-only inputs. Fallback editors do not participate: rechecks detect ordinary races, not filesystem CAS against uncooperative final check/rename races.
4. Stage exclusively created same-directory files, preserve safe file modes, sync content, and atomically rename every published file, including archives and journal state. Journal has its own version, transaction ID, exact intent, before/after hashes and recoverable staged bytes/backups. Persist/sync the journal before the first artifact replacement; retain it until the bundle is durably committed. Directory-sync support/limitations are explicit. Archives remain complete and exclusive; never publish half-written archives.
5. Multi-file rename is not an instantaneous filesystem transaction. On failure, return **recovery-required** with transaction ID, affected artifact states and next command; never ordinary success with partial state. Core readers detect an in-flight/pending journal and retry briefly or return explicit unverified/recovery-required output rather than treating mixed generations as a coherent fresh plan. Read-only commands never recover or create locks as a side effect.
6. Recovery is explicit through `workplan_update` with shared `recovery: "resume" | "rollback"`, mutually exclusive with ordinary update fields. Native recovery is orchestrator-only, requires `expectedHash`, all exact-path permissions and the same lock. It preflights every target: current bytes must equal journal's before or after hash (or matching absence). Any other/external state aborts without replacing that artifact, preserves all evidence, and requests parent reconciliation. Recheck before each recovery rename; idempotent restart is supported. No unconditional rollback over external edits. Invalid/corrupt journals fail closed.
7. Ordinary metadata updates/compaction preserve handwritten Markdown byte-for-byte. Generated Markdown can refresh only after a reliable exact comparison to the previous generated bytes. Restricted patch updates only the linked Markdown and preserves JSON bytes/markers. Reset is never an implicit resume action. Replacing non-generated Markdown through reset/full-content update/overwrite requires explicit replacement intent (shared `replaceMarkdown: true` where needed), stale-state protection and exact edit authorization; otherwise refuse, not regenerate. A move with missing source Markdown fails closed unless the caller explicitly supplies nonblank `planMarkdown`; never invent Markdown implicitly. Every changed normalized linkage must publish its exact new Markdown target with absent-before/non-null-after move shape; journal recovery rejects incomplete relinks before authorization. Keep existing blank-placeholder update guards and requested reset semantics.

**D. Checkpoints, dependencies, compaction and evidence**

1. New checkpoint sidecar format is versioned separately (use checkpoint version **2**), with manifest/`planHash`. Read checkpoint v1 for compatibility, but classify its multiartifact freshness as **unverified/legacy** even if JSON `sourceHash` matches. It cannot authorize apply. Malformed checkpoints produce diagnostics rather than hiding current plan state. Do not silently upgrade any checkpoint on a read.
2. `planFresh` means only the checkpoint's JSON/Markdown/spec manifest matches. `recentValidation` remains reported evidence, not tool-executed tests. Expose evidence verification separately as **unverified** unless actual receipts include independently checked code-state binding; never infer verified evidence from plan hashes, status or a worker's PASS. Compaction may update checkpoint plan binding but must not promote evidence freshness.
3. Explicit step dependencies live in optional `<id>.dependencies.json` (version **1**), with exact phase/step references and `dependsOn` edges; no mandatory core schema fields. Missing sidecar means **dependencies not recorded**, not inferred prerequisites. `workplan_update` can explicitly replace dependency metadata transactionally; reject dangling/ambiguous references and cycles. Resume/inspect retrieve this metadata. Compaction preserves dependencies needed by unfinished work and retains small terminal dependency summaries in the sidecar when completed referenced phases are archived; do not lose prerequisite context.
4. Preview is pure and returns `previewToken`, `stateHash`, canonical selection, exact removal digest/counts, write intent and `confirmationRequiredForApply: "ARCHIVE_SELECTED_HISTORY"`. Token hashes a versioned canonical payload: canonical root/plan ID, current state manifest (including checkpoint/specs/dependencies), reason, selected stable phase IDs, selected note/finding indexes **and their exact contents**, anticipated generated-Markdown treatment and removals. Hash tokens are state bindings, not credentials or approvals.
5. Apply requires exact confirmation **and** preview token **and** current native `expectedHash`, a checkpoint fresh for all plan artifacts, nonempty valid selection and authorization. Recompute token under lock; any artifact/reason/selection/removal change fails before archive or mutation. Checkpoint refresh changes stateHash, so order is update -> checkpoint -> preview -> authorized apply. Archive original JSON/Markdown/checkpoint and selected metadata before pruning; retain scope/nonGoals/constraints/open findings/unfinished work and at least one phase. Preserve handwritten Markdown. Successful apply refreshes checkpoint plan binding without inventing test evidence.

**E. Bounded continuation and diagnostics**

1. Resume shared inputs: `maxChars` (default **12000**, range **4096..64000**), `limit` (default **20**, range **1..100**), `cursor` (optional opaque snapshot-bound cursor), and exact optional phase/step filters. Budget includes serialized output; collection limits alone do not bound arbitrary strings. No full Markdown, receipt history or completed-step detail in default output.
2. Always reserve a compact safety/header envelope: hashes/freshness/warnings, current step (fresh checkpoint exact position if valid, otherwise deterministic active-step selection), recorded immediate dependencies, blockers and blocker/critical/major finding summaries. Then page active work and other findings/references. Stable order: current first; dependencies in recorded order; findings severity blocker/critical/major/minor/question/note then original index; other steps in phase/step order. Budget truncates details deterministically, with per-field truncation flags, total/returned/omitted and high-severity counts, snapshot-bound next cursor and exact read/inspect/sidecar pointers. An oversized safety set must show an overflow warning and omitted-danger counts, never appear complete.
3. Pagination returns each non-pinned item once; repeating the small pinned safety envelope is explicit. Reject stale cursor snapshots; repeated calls on unchanged bytes/options return the same packet. Paginated read/inspect retrieval exposes exact IDs/dependency metadata without requiring full history.
4. Stale/legacy checkpoint summary/nextAction must not drive execution; nextAction is null unless reconfirmed. Still surface recorded guardrails, blockers and references as **unverified checkpoint warnings**, distinguish them from current plan constraints, and require reconfirmation. No checkpoint warning is authorization to relax a guardrail. Evidence claims remain unverified.
5. Doctor accepts optional plan ID and bounded listing options. Core reports canonical/requested root, artifact/schema/link/freshness issues, sidecar classification and pending lock/journal recovery pointers. Native adapter supplies effective tool catalog, plugin/config facts and available agent/session permission facts using supported read APIs. Explicitly mark unavailable/unprovable permission facts **unknown** rather than allowed. Diagnose missing tools and builtin `opencode.plan` activation/conflict; distinguish effective registration from merely configured strings. Never repair/create/upgrade, ask permissions, change session rules or interrupt services.

**F. Native adapter and permission boundary**

1. Canonical root comes from `ctx.location.project.directory` and realpath; do not use a nested CWD or model-supplied workspaceRoot. Native schemas reject root overrides. Caller identity comes from trusted runtime context, not input fields. Keep native project-only behavior and symlink/external-directory guards.
2. Lifecycle writes create/update/patch/reset: **plan or orchestrator**. Checkpoint, compaction **apply**, and recovery: **orchestrator only**. All reads/inspect/list/validate/resume/doctor and compact preview: any caller whose effective rules authorize that read-only tool. Role guards supplement, never replace, runtime permissions. Planner authoring access does not grant production writes.
3. Register the twelve public core names (create/update/inspect/validate/read/list/patch/reset/resume/checkpoint/compact/doctor) plus pure native `workplan_compact_preview`, implemented through shared preview logic. Separate preview identity permits read-only authorization even when `workplan_compact` is ask/deny; reject injected apply mode. `workplan_compact` remains preview by default, with orchestrator guard applied only to apply. Do not map preview to blanket edit permission.
4. Native mutation authorization must cover both effective tool action and **every exact canonical edit resource** (JSON, linked Markdown if actually modified, checkpoint, archive, sidecar and transaction-owned paths), respecting agent rules, session overrides, explicit deny, last-match semantics and user ask/cancel. Do not widen to `*`, auto-reply to asks, change permission rules, trust an unrelated prior tool approval, or implement a partial homemade permission evaluator that misses session state. The legacy adapter's no-op `ask(edit)` must be removed, not renamed.
5. **Approved public bridge:** one native engineer owns detailed integration against public plugin/client **2.0.20**, with parent review. Obtain a candidate authenticated endpoint via supported `Service.discover` or explicitly configured endpoint/auth. Discovery and valid authentication alone are **not** proof of the executing host. Never access private permission services or silently use broader tool-level permission as a replacement.
6. **Host binding:** register a scoped public RPC challenge backed by a random, in-memory **per-plugin-instance nonce** bound to its canonical location. Candidate client must prove it reaches **THIS executing instance/location** before any permission request. Instance/proof mismatches, unknown host or connection failure are actionable fail-closed errors. Do not persist proof secrets, expose credentials in logs/doctor, or treat version/project-name similarity as binding. Reset/revalidate binding after plugin reload/connection change.
7. **Event readiness:** establish the authenticated public event stream, correlate it to the bound instance/location, then perform a public RPC nonce-echo challenge whose correlated event must be observed through that stream **before** creating a permission request. Merely opening a connection/subscription is insufficient. Readiness loss/disconnect fails closed, so an approval cannot be missed between request and subscription. Use invocation-local correlation/source IDs; ignore unrelated/replayed events and dispose listeners on completion/abort.
8. **Exact request and definitive result:** use supported public `permission.create` (`POST session/{sessionID}/permission`) for exact canonical edit resources, associated with trusted executing session/agent/tool source. Parent review verifies public API encoding; no invented ctx API or model-provided identity. Only definitive runtime **allow** authorizes the bound intent. An **ask** waits for the real correlated reply event; deny/reject/cancel errors. Never call `ctx.permission.reply`, client reply, or permission rules overrides to grant approval. Approval receipt binds instance/location/session/agent/source and exact intent; changed snapshot/resources require reread/new authorization, not widening an earlier grant.
9. **Cancellation:** native write invocation requires usable **AbortSignal**, not a synthetic never-aborted signal. Pass it through discovery/host proof/event readiness/request/wait/core engine and check before every operation and completion. Abort stops waiting; late approval or late network resolution cannot authorize or commit. Deny/reject and canceled requests remain failures even if a later event says allow. Unsupported signal/host/event capability produces explicit error and doctor capability diagnostics. Read-only tools remain available without requesting write approval.
10. **Actual-host gate:** bridge tests and disposable installed-host/cancel smoke must prove binding, event readiness and definitive approval semantics for the executing runtime; 2.0.20 package types do not prove a 2.0.19 host passes a signal or supports this flow. A missing capability blocks native writes/overall completion, not the independent core phase. Return the exact supported-host prerequisite, never insecure fallback or proposal-only “complete”. Unit mocks alone cannot satisfy requirement 6.
